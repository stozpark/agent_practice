# Commit Convention

## 커밋 메시지 형식

```
<type>(<scope>) <subject>

<body>

<footer>
```

---

## 언어 규칙

- 커밋 메시지는 **한글**로 작성합니다.
- 헤더의 타입은 `< >` 문자로 감싸서 표기합니다.
  - 예시: `<fix> 긴급Fix`

---

## Type (타입)

| 타입 | 설명 |
|------|------|
| `feat` | 새로운 기능 추가 |
| `fix` | 버그 수정 |
| `docs` | 문서 수정 (코드 변경 없음) |
| `style` | 코드 포맷팅, 세미콜론 누락 등 (기능 변경 없음) |
| `refactor` | 코드 리팩토링 (기능 변경 없음) |
| `test` | 테스트 코드 추가 또는 수정 |
| `chore` | 빌드 설정, 패키지 관리 등 기타 변경 |

---

## Scope (범위)

변경된 영역을 간략히 표기합니다. 생략 가능합니다.

예시: `auth`, `ui`, `api`, `config`

---

## Subject (제목)

- 50자 이내로 작성합니다.
- 마침표를 사용하지 않습니다.
- 명령형 현재 시제로 작성합니다. (예: `변경한다`, `추가한다`)
- **한글**로 작성합니다.

---

## Body (본문)

- 선택 사항입니다.
- 72자마다 줄 바꿈을 합니다.
- **무엇을**, **왜** 변경했는지 설명합니다.
- **한글**로 작성합니다.

---

## Footer (꼬리말)

- 선택 사항입니다.
- 이슈 번호를 참조할 때 사용합니다.

예시:
```
Closes #123
Refs #456
```

---

## 예시

```
<feat>(auth) 소셜 로그인 기능 추가

Google, Kakao OAuth 연동을 통해 소셜 로그인을 지원합니다.
기존 이메일 로그인과 함께 사용 가능합니다.

Closes #42
```

```
<fix> 긴급Fix
```

```
<fix>(api) 사용자 조회 시 null 반환 오류 수정
```

```
<docs> 커밋 컨벤션 초안 작성
```
